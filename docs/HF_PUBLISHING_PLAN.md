### Body sections (1-2 short paragraphs each)
1. **Model description** — Chinese-text 34-way classifier predicting the active Socratic-teaching state of a student turn. Drop-in replacement for the LLM-consultant call in the KELE pipeline (`socratic_teaching_bert_consultant.py`).
2. **State taxonomy** — 35 states across 5 stages (a/b/c/d/e), inherited from SocRule.
3. **Use case** — load via `--bert-consultant <hf-id>` in `kele.py` evaluation.
4. **Training data** — SocratDataset train split (~42K labeled turns), 90/10 split with 5% in-domain eval held out; seed=42.
5. **Training procedure** — exact CLI invocation including `--model-id`, `--freeze-backbone` or `--lora`, `--batch_size`, `--gradient-checkpointing` where applicable. Reference `scripts/train_state_classifier_34way.py` in the project repo.
6. **Evaluation** — table copied from `test_eval.json`: overall + per-stage (a/b/c/d/e), n_test_turns, n_dialogues.
7. **Funnel comparison** — table of all 5 candidates side-by-side; cross-link to the other 4 repos. This is the killer feature; lets readers see the ablation at a glance.
8. **How to use** — 4-line code snippet:
   ```python
   from transformers import AutoModelForSequenceClassification, AutoTokenizer
   tokenizer = AutoTokenizer.from_pretrained("maxjkh/socrates-state-classifier-...")
   model = AutoModelForSequenceClassification.from_pretrained("maxjkh/socrates-state-classifier-...")
   logits = model(**tokenizer("学生: 什么是化学键？", return_tensors="pt")).logits
   ```
9. **Limitations** — Chinese-only training data; school-chemistry domain; single dataset; no out-of-distribution validation.
10. **Citation** — bibtex pointing to the project paper draft + Sun et al.'s original KELE paper.
11. **License** — Apache 2.0 (verify Qwen3 + Qwen3.5 license terms before publish; if any candidate's base model is under a more restrictive license, downgrade accordingly).

## Tooling (three small additions to `scripts/`)

To be written when Max has HF account ready. None of this needs to exist before then.

### 1. `scripts/build_model_cards.py` (~80 lines, offline)
Inputs:
- `--results-dir results/<dir>/` (one or more)
- `--repo-name <hf-namespace>/<slug>` paired with each results dir
- `--training-config <args>` (epochs, batch_size, lr, lora-r, etc. as kwargs)

Outputs:
- `<results-dir>/README.md` (model card with filled-in frontmatter + body)
- `<results-dir>/training_config.json` (hyperparameters)
- `<results-dir>/eval_results.json` (copy of test_eval.json, but at the top level for convention)

Behavior:
- Reads `<results-dir>/test_eval.json`
- Computes weighted stage accuracy (across the 5 stage groups)
- Generates the cross-link "Funnel comparison" table by accepting a `--funnel-manifest funnel.json` listing all 5 candidates and their accuracies

### 2. `scripts/publish_to_hf.py` (~50 lines, needs `HF_TOKEN`)
Inputs:
- `--results-dir <dir>` and `--repo <hf-id>`
- `--dry-run` (default off): list what would be uploaded without uploading
- `--public` (default off): create as private first, switch to public via the web UI after sanity check

Behavior:
- Uses `huggingface_hub.HfApi`:
  - `create_repo(repo_id, exist_ok=True, private=not args.public)`
  - `upload_folder(folder_path=<dir>, repo_id=<repo>, repo_type="model", ignore_patterns=["checkpoints/*", "*.pt", "train.log"])`
- Prints the resulting URL.

### 3. `scripts/make_hf_collection.sh` (~20 lines, wraps the above)
For-loop over the 5 funnel candidates: build model card, then publish. With `--dry-run` first, then real run after eyeballing the cards.

## Open questions for execution day

- **HF org or personal user?** `maxjkh` (personal) is the simplest. If the project gets a lab org later, repos can be transferred via the web UI.
- **Public from day 1 or private first?** Recommend `--public=false` for first push (creates private), eyeball each repo's landing page, then switch to public via web UI. ~30 sec of extra friction, big safety net.
- **Adapter-only branches for T2/T4?** The merged-model artifact (~2.3 GB) is what users actually need. If repo size becomes a concern, we can add a `lora-only` branch with just the ~9 MB adapter. Not blocking.
- **One README pattern vs five per-model READMEs?** Decided: five per-model READMEs (best for HF Hub discoverability), with each cross-linking to the others. The Collection page acts as the umbrella.
